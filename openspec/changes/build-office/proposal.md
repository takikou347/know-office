## Why

know-office は、オーナーが AI の社員とその成果を管理する管理室である。この仕様が要件の正本で、どう作るかの設計書は非公開の knowidea にある。

## What Changes

- 管理するものを「Claude の管理」と「サービスの管理」の 2 つに限り、ほかは管理の拡張として差し込む形で作る
- 社員 3 人が、勤務の時間の中で目的から自分でタスクを作って進める。社長とレビュー担当は Opus 5.5、開発担当は Sonnet 5.5
- 勤務は 1 日 8 時間を基本にし、チェックポイントとオーナーの指示で伸び縮みする。勤怠は実際の動きから付け、日ごとにしたタスクを出す
- 変更の確認は GitHub の画面に移らず、know-office のレビューで行う
- アイデアから運用までを 1 本で管理する。最初のサービスは knowidea-ui、2 番目は know-office 自身
- 設定と記録は、office の物とサービスごとの物に分ける
- 社員を止めるのはシステムの自動停止で、オーナーの操作は補助にする
- Cloudflare の 1 つのアカウントで組む。すべて TypeScript。画面は Vite と React、ゲートウェイは Hono で、1 つの Worker から配る

お金と外部連携は次のとおり。どれもオーナーと決めた。

- Cloudflare の有料プランの月 5 ドルは承認済み。社員を 1 日 8 時間動かす事もオーナーが決め、ワークスペースの使用分を足して月 15 ドル前後になる。ワークスペースを勤務の間起こし続けると 19 ドルほどになりうるので、超える時はオーナーに聞く
- 外部連携は GitHub、Claude の API、Google の 3 つ。これより増やす時はオーナーに聞く。通知は画面に出す。オーナーは独自のドメインを取らず、メールの通知を画面の通知で代えると決めた

## Capabilities

### New Capabilities

- `work-loop`: 目的からタスクを作り、社員が自分で進める繰り返し
- `workday`: 勤務の時間と勤怠
- `screens`: 画面の一覧と、端末、速さ、言葉の決まり
- `review`: 変更を読み、直し、承認と差し戻しを出すレビューとエディタ
- `services`: アイデアから運用までのサービスの管理と、サービスごとの設定と記録
- `auto-stop`: 自動で止まるセキュリティ、シグナルの数え方、止めた記録と蒸留
- `security`: ログイン、鍵、オーナーの情報、不正アクセスへの備え
- `monitoring`: 監視、障害への強さ、見つけて直す仕組み、費用を抑える工夫
- `github`: GitHub App での連携とルール
- `extensions`: 管理の拡張の差し込み口

### Modified Capabilities

無し。

## Impact

- このリポジトリを、画面、共通パッケージ、ゲートウェイ、ワークスペースに分ける
- knowidea-ui に、変更を見せるコンポーネントとエディタのコンポーネントを足してバージョンを上げる
- オーナーの作業は最初の 1 回だけ。Cloudflare の申し込みと鍵の登録、Google Cloud のログイン用の鍵とパスキーの登録、GitHub と連携するボタン
