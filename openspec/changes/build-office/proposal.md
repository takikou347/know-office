## Why

know-office は、オーナーが AI の社員とその成果を管理する管理室である。要求はオーナーと Claude Doc「know-office 要求定義書」で詰め終えたので、作る元になる仕様をこのリポジトリに移す。以後はこの仕様が正本で、要求定義書は経緯を読む物になる。

## What Changes

- 管理するものを「Claude の管理」と「サービスの管理」の 2 つに限り、ほかは管理の拡張として差し込む形で作る
- 社員 3 人が、勤務の時間の中で目的から自分で仕事を作って進める。社長と見る役は Opus 5.5、作る役は Sonnet 5.5
- 勤務は 1 日 8 時間を基本にし、区切りとオーナーの指示で伸び縮みする。勤怠は実際の動きから付け、日ごとにした仕事を出す
- 変更の確認は GitHub の画面に移らず、know-office のレビューの画面で行う
- アイデアから運用までを 1 本で管理する。最初のサービスは knowidea-ui、2 番目は know-office 自身
- 設定と記録は、office の物とサービスごとの物に分ける
- 社員を止めるのはシステムの自動の守りで、オーナーの操作は補助にする
- Cloudflare の 1 つのアカウントで組む。すべて TypeScript。画面は Vite と React、入口は Hono で、1 つの Worker から配る

作らない物は次のとおり。

- コードやコンテンツの置き場。GitHub と各サービスに置く
- 各サービスの中身の画面
- アプリの中の費用の上限。Anthropic の契約側の上限に任せる
- 記録を消す機能、社員の名前、組織ごとに分ける仕組み

お金と外部連携は次のとおり。どれも要求定義書でオーナーと決めた。

- Cloudflare の有料プランの月 5 ドルは承認済み。社員を 1 日 8 時間動かす事もオーナーが決め、作業場の使用分を足して月 15 ドル前後になる
- 外部連携は GitHub、Claude の API、Google の 3 つ。これより増やす時はオーナーに聞く。メールの送り方は Cloudflare の中で済むかが未確認で、済まなければオーナーに聞く

## Capabilities

### New Capabilities

- `work-loop`: 目的から仕事を作り、社員が自分で進める繰り返し
- `workday`: 勤務の時間と勤怠
- `screens`: 画面の一覧と、端末、速さ、言葉の決まり
- `review`: 変更を読み、直し、可否を出すレビューとエディタ
- `services`: アイデアから運用までのサービスの管理と、サービスごとの設定と記録
- `auto-stop`: 自動で止まる守り、合図の数え方、止めた記録と蒸留
- `security`: ログイン、鍵、オーナーの情報、不正アクセスへの備え
- `monitoring`: 監視、障害への強さ、見つけて直す仕組み、費用を抑える工夫
- `github`: GitHub App での連携とルール
- `extensions`: 管理の拡張の差し込み口

### Modified Capabilities

無し。

## Impact

- このリポジトリを、画面、共通の部品、入口、作業場に分ける
- knowidea-ui に、変更を見せる部品とエディタの部品を足して版を上げる
- オーナーの作業は最初の 1 回だけ。Cloudflare の申し込みと鍵の登録、Google Cloud のログイン用の鍵とパスキーの登録、GitHub と連携するボタン
