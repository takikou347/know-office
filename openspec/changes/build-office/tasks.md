## 0. 進め方

- 費用のかからない項目を、Claude Code のクラウドの開発環境で先にすべて作る。画面、API と D1、Durable Objects は wrangler の開発用の実行とテストで、ワークスペースは開発環境の Docker と wrangler の Containers の開発用の実行で確かめる
- 4.0a で、テスト用の鍵で署名したログインの証明、仮想の認証器によるパスキー、決まった返事を返す偽物の Claude API と GitHub API を作る。開発環境ではこれらを Cloudflare Access、本物の API、本物の GitHub の代わりに使う
- 4.1 は開発環境の Containers で外向きの通信を絞れるかを先に確かめ、7.1 と 7.2 の前に構成を決める。本物の Cloudflare での確かめは最後に 4.1b で行い、そこで絞れないと分かれば、フォールバック構成に切り替えて 7.1 と 7.2 を作り直す
- 本物の環境が要る次の項目は、開発環境の項目が済んでから最後にまとめて行う: 2.5 の npm への公開、4.1b の本物の Cloudflare での確かめ、4.2、4.8、4.9、7.6 の費用の測定、8.4、8.6、8.8、8.9 の本物の GitHub とのつなぎ、9.11 の本物の Claude API のバッチ処理、10.2 のデプロイした先への自動の攻撃のチェック、10.3
- このうち費用が増える項目と外部連携に当たる項目、つまり 4.2、4.9、7.6、8.4、9.11、10.3、2.5、フォールバック構成で費用が変わる時の 4.1b は、各項目の前にオーナーに聞き、はい の後に進める
