## ADDED Requirements

### Requirement: ボタン 1 つで連携する

オーナー SHALL 設定の画面の「GitHub と連携する」を押し、GitHub の画面で「作成」と「インストール」を押すだけで連携できる。know-office 専用の非公開の GitHub App を作り、オーナーのアカウントにだけ入れる。

#### Scenario: 連携する

- **WHEN** オーナーが連携のボタンを押し、GitHub の画面で 2 回押す
- **THEN** App が作られて入り、選んだリポジトリが know-office から見える

#### Scenario: やめる

- **WHEN** オーナーが GitHub の画面で App を外す
- **THEN** know-office から GitHub の操作ができなくなる

### Requirement: App の鍵

App の元の鍵 MUST 鍵の置き場に置き、ゲートウェイだけが読む。GitHub を呼ぶ時は、リポジトリ 1 つと要る操作だけに絞った、1 時間で切れる鍵をゲートウェイが作って付ける。ワークスペースには GitHub の鍵を渡さない。App は、オーナーが選んでいないリポジトリ、アカウントの設定、支払いには届かない。

#### Scenario: 絞った鍵

- **WHEN** ワークスペースが knowidea-ui への push をゲートウェイに頼む
- **THEN** ゲートウェイは knowidea-ui だけに書ける 1 時間の鍵を付けて GitHub に送る

#### Scenario: 選んでいないリポジトリ

- **WHEN** 社員が連携で選んでいないリポジトリへの操作を求める
- **THEN** ゲートウェイが断る

#### Scenario: 全体が止まる

- **WHEN** 自動停止が全体を止める
- **THEN** 発行した 1 時間の鍵が取り消され、元の鍵は know-office で使えなくなる
- **AND** オーナーが再開する時、新しい元の鍵の作り方が 1 ページで示される

### Requirement: GitHub のルール

オーナー SHALL 社員が GitHub で何をしてよいかを設定の画面で決められる。設定の画面に初期値を置き、1 は office 全体の設定で、サービスのリポジトリはこの中から選ぶ。2 から 5 はサービスごとの設定で変えられる。6 は office 全体とサービスごとの両方で使える。

1. 触れるリポジトリ。初期値は連携したものすべて
2. できる操作。読む、ブランチを作る、push、プルリクエスト、main へのマージ、Issue。初期値はすべて
3. main ブランチに入れる条件。初期値はチェックとレビュー担当の承認
4. 本番にデプロイする条件。初期値はオーナーの承認。knowidea-ui はサービスごとの設定でチェックとレビュー担当の承認にする
5. 触れない所。初期値は GitHub Actions の設定と鍵の設定
6. 手で止める。初期値は止めない

#### Scenario: できる操作を絞る

- **WHEN** オーナーがあるサービスで main へのマージを外す
- **THEN** 社員がそのリポジトリでマージを求めるとゲートウェイが断る

#### Scenario: 触れない所

- **WHEN** 社員が GitHub Actions の設定を変える push を求める
- **THEN** ゲートウェイが断り、ルールの外の操作として数える

### Requirement: ブランチの保護をルールから掛ける

know-office SHALL main ブランチに入れる条件を、公開のリポジトリでは GitHub のルールセットとして掛け、非公開のリポジトリではゲートウェイの判断で守る。main を進めるのはゲートウェイだけとする。オーナーが GitHub の設定を触る事は無い。

#### Scenario: 条件を変える

- **WHEN** オーナーが main ブランチに入れる条件にオーナーの承認を足す
- **THEN** 公開のリポジトリでは GitHub の側のルールセットも同じ条件になる
- **AND** 非公開のリポジトリでは、ゲートウェイが条件を満たすまで main を進めない

### Requirement: 通知を受ける

know-office SHALL プルリクエストやチェックの結果を GitHub からの通知で受け、社員とタスクの画面に出す。

#### Scenario: チェックが終わる

- **WHEN** GitHub からチェックの結果の通知が届く
- **THEN** レビューのチェックの結果が新しくなる

### Requirement: App を通した操作を記録する

App を通した操作 MUST すべて記録し、普段と違う動きは自動停止に渡す。

#### Scenario: 操作の記録

- **WHEN** 社員がプルリクエストを出す
- **THEN** どの社員がどのタスクで出したかが記録に残る
