## ADDED Requirements

### Requirement: 気付く

know-office SHALL 故障、遅れ、上限への到達、ルールの外の操作、続く失敗、怪しい動きを 5 分以内に知り、画面とメールで知らせる。入口、社員の状態、作業場を 1 本の流れとして追い、5 分ごとに自分の様子を確かめる。記録は、必要になったら OpenTelemetry で外に出せる形で持つ。

#### Scenario: API の失敗が続く

- **WHEN** Claude の API が 5 分に 3 回失敗する
- **THEN** 5 分以内に画面とメールで知らせが出る

#### Scenario: 1 本の流れで追う

- **WHEN** オーナーの操作が入口から社員の状態、作業場へ渡る
- **THEN** 3 つの記録を 1 つの流れとして読める

### Requirement: 記録に出す値

know-office SHALL 社員ごとの動き、API の失敗、トークンと費用、作業場の稼働時間を記録の画面に出す。使った額はいつでも見えるようにし、アプリで費用の上限は置かない。

#### Scenario: 今月の費用

- **WHEN** オーナーがダッシュボードを開く
- **THEN** 今月の使った額が出る

### Requirement: 落ちても続きから

社員 SHALL 区切りごとに状態を残し、落ちても続きから始める。Claude の API が止まった時や上限に達した時は、待ってから続きを行う。

#### Scenario: API の上限

- **WHEN** Claude の API が上限を返す
- **THEN** 社員は待ち、解けた後に同じ仕事の続きを行う

### Requirement: 止まらなさ

know-office SHALL 月の稼働率 99.9% を目安とし、月ごとの値を記録の画面に出す。

#### Scenario: 稼働率を見る

- **WHEN** オーナーが記録の画面を開く
- **THEN** 5 分ごとの確かめから出した今月の稼働率が出る

### Requirement: 記録を戻せる

記録 MUST 消さない。30 日分は時点を指定して戻せるようにし、それより前は毎日別の置き場に写す。

#### Scenario: 1 日前に戻す

- **WHEN** データベースが壊れる
- **THEN** 1 日前までの時点に戻せる

### Requirement: 記録の量

記録を消さずに続けられるよう、know-office SHALL データベースの使った量を見て、上限の 8 割に届いたらオーナーに知らせ、古い記録を読むだけの置き場に分ける。

#### Scenario: 8 割に届く

- **WHEN** 記録のデータベースの使った量が上限の 8 割に届く
- **THEN** オーナーに知らせが出て、記録の画面に使った量が出る

#### Scenario: 前の年を読む

- **WHEN** オーナーが前の年の勤怠を開く
- **THEN** 分けた置き場から読めて、今の年と同じ表で出る

### Requirement: 見つけて直す

見る役 SHALL 週に 1 度、記録からエラーの原因、遅い所、無駄な費用を調べ、根拠を付けて GitHub の Issue を作る。急ぐ故障は見つけた時に作る。対象は know-office 自身と、管理しているサービスの両方とする。

- エラーの原因: 同じ原因をまとめた Issue 1 件。起きた回数と再現の手順を付ける
- 遅い所: 目安を超えた物を遅い順に並べた Issue
- 無駄な費用: 設定や指示の文の直しの案

#### Scenario: 同じ原因をまとめる

- **WHEN** 同じ原因の失敗が 1 週間に 12 回起きる
- **THEN** Issue が 1 件作られ、回数と再現の手順が付く

#### Scenario: 効き目を確かめる

- **WHEN** 作る役が Issue を直して入れる
- **THEN** 直した後の 7 日の値を前と比べ、効き目を Issue に書いて閉じる
- **AND** 効かなければ元に戻す

#### Scenario: 費用が増える直し

- **WHEN** 直しに費用が増える事か、外部との新しい連携が要る
- **THEN** オーナーに上げる

### Requirement: トークンを減らす

know-office SHALL 同じ仕事を少ないトークンで終える工夫を土台に入れる。変わらない部分を毎回同じ形で先頭に置いて読み直しを安くし、役と仕事でモデルを分け、考える深さを会話は浅く、作る仕事は中くらい、見る仕事は深くと決め、渡す物を細くし、急がない仕事は一括処理で回す。送る前にトークンを数え、使った量と読み直しの割引の当たりを仕事ごとに記録する。

#### Scenario: 読み直しの割引

- **WHEN** 同じ社員が 5 分以内に続けて 2 回 Claude を呼ぶ
- **THEN** 2 回目は先頭の変わらない部分が割引で読まれ、当たりが記録に残る

#### Scenario: 急がない仕事

- **WHEN** 止めた記録の蒸留、記録の調べ、アイデア出しのどれかを行う
- **THEN** 作業場を通さず、入口が一括処理で回す
