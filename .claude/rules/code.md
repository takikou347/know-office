# コードの書き方

正本はこの rules。ここにはチェックで落ちない決まりだけを置く。lint で落ちる決まりは、書いたファイルをフックがその場で lint して返すので、返った所を直す。

## 名前と置き場

- 置き場は `../knowidea/services/know-office/docs/04-detail/index.md` の 2 章。ゲートウェイ `apps/office/src/gate/`、画面 `apps/office/src/screen/`、ワークスペース `apps/workspace/src/`、共通 `packages/core/src/`、Web アプリのサービスが訪問と 5xx を書く共有の型 `packages/requests/src/`
- 関数と変数は lowerCamelCase、型とコンポーネントは PascalCase、決まった値の並びは UPPER_SNAKE_CASE
- テーブルとカラムは snake_case。時刻は `<動き>_at` (協定世界時のミリ秒)、日本時間の日は `day`
- Zod スキーマは `<動き><物>Input`、返す形の型は物の名前 (`CreateNodeInput`、`NodeDetail`)
- 名前は英語、コメントとテストの名前は日本語

## 型と境目

- 外から来る物 (画面の入力、GitHub の通知、ワークスペースからの要求、Claude のツールの入力、D1 の JSON のカラム、R2 から読んだ物) は `unknown` で受け、`packages/core/src/schemas/<物>.ts` の Zod スキーマで確かめてから使う
- 行の型は Drizzle の `$inferSelect` と `$inferInsert`、入力の型は `z.infer` から取り、手で書き写さない
- 種類は文字列の合わせと `as const` の並びで書き、`enum` を使わない
- 画面で選ぶ選択肢 (モデル、職種、状態、段階、種類など) はマスタデータにし、`packages/core/src/master/<物>.ts` に 1 つの物ごとに 1 ファイルで `defineMaster` で置く。画面は `@know-office/core/master/<物>` から `optionsOf` と `labelOf` で選択肢と名前を作り、ゲートウェイは `masterSchema` で確かめる。画面に名前の表を別に書かない
- 秘密と鍵は `Secret` で持ち、記録と返事に出さない
- ID は `core` の `newId()` (UUID v7)、日本時間への直しは `jstDay(at)` と `jstClock(at)` だけ

## 書き方

- 否定は早く返すガード (`if (!session) throw ...`) と、否定の側にしか処理の無い所だけに使う
- 想定した失敗は `core` の `AppError(code, message)` を投げる。想定外は `internal` にし、中身は `log` と `error_events` (エラーログ) にだけ残す。オーナーの情報、鍵、作業トークンを記録の文に入れない
- セキュリティに関わる判断は、届かない、遅い、形が違う時は断る側に倒す
- 今の時刻は引数で受けた `Clock` の `now()` を使い、`Date.now()` を直に呼ばない
- 外を呼ぶ時は `AbortSignal.timeout()` を付ける。初期値は 10 秒、ルールの判断は 5 秒
- D1 にまとめて書く時は `db.batch()`、`audit_log` は記録 DO を通す
- 行を消すマイグレーションは、その行を ID で指す表 (指摘、GitHub への写しなど) を同じマイグレーションで残す行へ付け替えるか消し、孤児を残さない。追記だけの表は守りのトリガーを外して付け替え、同じマイグレーションで付け直す
- 同じ行を条件付きで書く文 (同じ物を立てる入口が複数ある時など) は、どの入口の条件にも同じ守り (承認が消えたままか、など) をそろえる。1 つの入口だけに足した守りは、別の入口との競り合いで抜ける
- 費用が出る新しい口 (Claude の API の呼び出し、Cron、外のサービス) は、初期値 off の設定で閉じて入れ、オーナーの はい の後に開く。開いた後も 1 回と 1 日の上限を数で持つ
- 外の API (GitHub、Claude) は、件数とページの上限、返す形を公式の文書で確かめ、出典を `//` に書く。テストで使う模擬の GitHub と Claude API にも同じ上限と振る舞いをさせる
- 外へ書く送信 (コメント、レビュー、コミット、Issue) を送り直す所は、送れた後に記録が落ちても二重に送らない形 (本文の目印か冪等キーで、送る前に確かめる) にする
- 外の「今の値」を上書きする送信 (ステータスなど) を送り直す所は、積んだ時の値でなく送る時の値を読んで出す。古い送り直しが新しい送信の後に届いても、今の値に戻る形にする
- DO の中で持ち主の印 (起こした訳、役を取った者) を替える時は、読んでから替えるまで await を挟まず、ほかの持ち主の印は上書きしない。同じ時に来た物は、途中の物を待ってから確かめ直す
- 待ち合わせの約束 (ほかの要求が終えるのを待つ物) には期限を付け、期限で解いて待つ側が自分でやり直す。解く側は自分の印の時だけ解く
- 定期の確かめが合わない時に処理 (社員や全体) を止める判断は、正しい変更の途中 (書く順の間) に誤って止めない猶予を持つ。1 回の要求の中のセキュリティの判断は、今までどおり断る側に倒す

## コメント

- ファイルの頭に、受け持ちを `//` で 1 行
- 外に出す関数、型、定数、Zod スキーマ、DO のメソッドに JSDoc。1 行目は何をするかを 1 文、`@param` と `@returns` に説明、`AppError` を投げるなら `@throws` に `code` と投げる時。型は書かない
- React のコンポーネントは props の型の項目ごとに JSDoc
- `//` は「なぜ」と前提だけ。外の決まりに合わせた所は出典 (`// RFC 9457 の 3.1`)。日本語の常体で結論から
- `TODO` は `// TODO(#<Issue の番号>): <する事>` だけ。コメントアウトしたコードを残さない

## 依存

- バージョンを固定し (`^` を付けない)、`pnpm-lock.yaml` を一緒にコミットする
- Workers と Node の両方か使う側で動き、保守されている物だけ。画面の部品は knowidea-ui を先に探す
